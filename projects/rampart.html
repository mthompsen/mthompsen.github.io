Rampart

Hardens a fresh Rocky Linux 9 server toward the DISA RHEL 9 STIG with Ansible, proves it with OpenSCAP scans before and after, and exports NIST SP 800-53 evidence as OSCAL.

STIG pass rate
38.5% → 94.4%
still failing
24, each a documented exception
  • Target and method: one Rocky Linux 9.8 lab VM under QEMU/KVM, scanned with OpenSCAP and SCAP Security Guide 0.1.82 using the DISA RHEL 9 STIG profile. Baseline: 163 pass, 260 fail (38.5%). After make harden, a reboot and a re-scan: 404 pass, 24 fail (94.4%). Scan results in results/ come only from oscap and none was edited by hand.
  • Hardening: 16 roles (ssh, audit, pam, accounts, sysctl, kmods, packages, services, mounts, sudo, crypto with the FIPS:STIG policy, logging, network, aide, files, boot). Every task is tagged with its STIG ID and SSG rule name, so ansible-playbook --tags <rule> applies a single rule. The second playbook run reports changed=0, and SSH access is verified after hardening.
  • Exceptions: exceptions.yml lists 25 rules not remediated in the lab, each with a written justification: partitioning that must be decided at install time, a GRUB password that needs an operator's secret, remote log encryption and DNS that need site infrastructure, and SSG MAC rules that contradict the FIPS crypto policy (FIPS was kept).
  • Evidence: tools/gen_mapping.py maps each rule to STIG ID, CCI (from DISA's RHEL 9 STIG V2R8 XCCDF) and 800-53 Rev 5 control (from DISA's CCI list). 437 of 1,540 rules map; the rest are outside the STIG profile and marked unmapped with that reason. python -m rampart oscal emits OSCAL 1.1.3 assessment-results that validate against NIST's schema.
  • Testing and limits: Molecule converge, idempotence and verify against the VM, pytest for the report and export code, lint in CI. Molecule is not run in CI because the runners have no KVM image. Castellan, the intended consumer of the OSCAL export, has no import command yet, so no import is claimed.
