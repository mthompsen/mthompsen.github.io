Lodestone

An x86-64 Linux debugger in C built on ptrace: int3 breakpoints, instruction stepping, disassembly, backtraces and strace-style syscall tracing.

  • Architecture: about 3,300 lines of C11. include/lodestone.h holds the central debugger_t state, src/inferior.c owns the ptrace lifecycle and stop classification, src/repl.c dispatches 17 commands, and each feature lives in its own module (breakpoint.c, symbols.c, backtrace.c, syscall.c, capture.c). Capstone is the only external dependency. ASLR is disabled in the child via ADDR_NO_RANDOMIZE for reproducible addresses.
  • Breakpoints and stepping: break <symbol> or break *<addr> saves the original byte and writes 0xCC. On SIGTRAP the debugger rewinds RIP by one and restores the byte; resuming single-steps the original instruction with PTRACE_SINGLESTEP, re-plants the int3, then continues. Disassembly reads through a breakpoint shadow so planted int3s never appear. Memory uses process_vm_readv, with a /proc/<pid>/mem fallback for writes to read-only text.
  • Symbols, stack and syscalls: ELF .symtab and .dynsym are parsed directly, with no libelf. PIE load bias comes from AT_ENTRY in /proc/<pid>/auxv. backtrace walks the saved rbp chain with prologue sniffing. Syscall tracing uses PTRACE_SYSCALL with PTRACE_O_TRACESYSGOOD and PTRACE_GET_SYSCALL_INFO, and named catchpoints stop the target. Attach uses PTRACE_SEIZE; detach releases the process without killing it.
  • Interfaces: a command-line REPL, a JSON event mode that emits one event object per line, and a browser GUI. gui/server.js bridges the event stream to the browser over Server-Sent Events, so the GUI shows the same stops, registers, disassembly and syscalls as the terminal. Testing: each milestone has a bash gate.sh with assertions, and a milestone is committed only when its gate passes. The m12 gate rebuilds with -fsanitize=address,undefined and runs a full session with zero reports. The GUI has its own milestone gates, which drive headless Chromium through Playwright.
  • Limits, by design: single-threaded x86-64 Linux targets only. No threads, no hardware watchpoints, no DWARF line or variable info (symbol level only), no remote protocol, and no source-level step over, only stepi. Attaching to a process that isn't a child needs ptrace_scope=0 or CAP_SYS_PTRACE.
